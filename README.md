
# Document Q&A Assistant (RAG) with Citations

**Live demo:** https://meghana-rag-assistant.streamlit.app

Ask questions over your own PDFs. Every answer cites the exact source passage, and the assistant says "I don't know" when the documents don't contain the answer.

## Architecture

```
PDFs -> chunking -> embeddings -> FAISS (dense) \
                 -> BM25 (keyword)               -> RRF fusion -> cross-encoder rerank -> LLM -> answer + citations
```

## Results

Evaluated on **40** questions generated by an LLM from random passages of the documents (the source file and page were recorded automatically). Metrics: hit@5 (is the correct page in the top 5 results?) and MRR (how high the correct page ranks). The test set is small, and the questions share vocabulary with the passages, which favours keyword search, so treat these numbers as indicative, not definitive.

| Retrieval mode | hit@5 | MRR |
|---|---|---|
| dense | 0.925 | 0.796 |
| bm25 | 0.925 | 0.896 |
| hybrid (RRF) | 0.950 | 0.877 |
| hybrid + rerank | 0.975 | 0.925 |

## Run it

```bash
pip install -r requirements.txt
# put your PDFs in data/docs/
python -m src.ingest                 # build the index

export LLM_API_KEY=...               # plus LLM_BASE_URL / LLM_MODEL if not using OpenAI
streamlit run app.py
```

## Evaluate

```bash
# edit eval/questions.json first: question + the source file and page holding the answer
python -m eval.evaluate
pytest
```

## Tech stack

Python, PyMuPDF, sentence-transformers, FAISS, rank-bm25, cross-encoder reranking, OpenAI-compatible LLM API, Streamlit.

## Limitations and next steps

- Character-based chunking; try sentence- or heading-aware chunking.
- Retrieval is evaluated by page match; add answer-faithfulness checks (e.g., RAGAS).
- Add Docker and a GitHub Actions workflow that runs `pytest`.
